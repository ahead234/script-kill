# 注册页面交互测试用例

覆盖注册页（`/register`）的实时校验、交互行为、提交反馈与响应式表现。
自动化部分见 `src/test/java/com/example/scriptbooking/util/RegistrationValidationTest.java`。

## 一、测试环境

| 项目 | 说明 |
|---|---|
| 浏览器 | Chrome / Edge 最新版、Firefox 最新版、Safari 16+（macOS） |
| 移动端 | Chrome DevTools 设备模拟 375×667、414×896；或真机 375px 宽度 |
| 服务端 | Tomcat 9 + MySQL 8，访问 `http://localhost:8080/<context>/register` |
| 自动化 | `mvn test -Dtest=RegistrationValidationTest` |

## 二、功能与交互用例

| 编号 | 场景 | 操作步骤 | 预期结果 |
|---|---|---|---|
| R-01 | 页面加载 | 打开 `/register` | 显示用户名、手机号、密码、确认密码、协议勾选、注册按钮、返回登录链接；无控制台报错 |
| R-02 | 用户名格式 | 输入 `abc` 后移出焦点 | 立即提示“用户名需为 4-20 位字母、数字或下划线”，输入框标红 |
| R-03 | 用户名合法 | 输入 `player_09` | 错误提示消失，输入框显示成功态（绿色边框） |
| R-04 | 手机号位数不足 | 输入 `1380000100` | 提示“手机号需为 11 位数字，当前 10 位” |
| R-05 | 手机号超长 | 输入 12 位数字 | 只保留前 11 位（输入被截断），按 11 位规则校验 |
| R-06 | 手机号含非数字 | 输入 `138abc00001` | 非数字字符被自动剔除，输入框只剩数字 |
| R-07 | 手机号号段错误 | 输入 `12800001004` | 提示“手机号格式不正确，应以 1 开头且第二位为 3-9” |
| R-08 | 密码强度 | 依次输入 `abc`、`abc12345`、`abc12345!x9` | 强度条依次显示 弱 / 中 / 强，颜色与宽度随之变化 |
| R-09 | 密码规则 | 输入 `abcdefgh`（纯字母） | 提示“密码需同时包含字母和数字” |
| R-10 | 两次密码不一致 | 密码 `abc12345`，确认密码 `abc123456` | 确认密码下方提示“两次输入的密码不一致”；修改密码时该提示自动刷新 |
| R-11 | 密码显隐 | 点击密码框右侧“显示 / 隐藏” | 输入内容明文/密文切换，按钮文字与 `aria-label` 同步变化，焦点保持 |
| R-12 | 协议未勾选提交 | 其余字段合法，不勾选协议直接提交 | 阻止提交，协议下方提示“请先阅读并同意用户协议和隐私政策” |
| R-13 | 协议与隐私链接 | 点击《用户协议》《隐私政策》 | 新标签页打开 `/terms`、`/privacy`，原页面表单内容不丢失 |
| R-14 | 提交成功 | 填写合法用户名（未被占用）、11 位手机号、强度合格密码，勾选协议后提交 | 跳转到登录页并显示绿色提示“注册成功，请使用「用户名」登录”；用新账号可登录 |
| R-15 | 用户名重复 | 使用已存在的用户名（如 `player`）提交 | 停留在注册页，用户名下方提示“该用户名已被注册”，其余已填内容保留 |
| R-16 | 手机号重复 | 使用已注册手机号（如 `13800001004`）提交 | 停留在注册页，手机号下方提示“该手机号已被注册” |
| R-17 | 防重复点击 | 提交瞬间连续点击按钮 3 次 | 按钮只响应一次：点击后立即禁用并显示“注册中…”，不会产生两条用户记录 |
| R-18 | 重复提交（刷新/后退） | 注册成功后回退到注册页再次提交 | 提示“表单已过期或已提交，请重新填写后再试”，不会重复创建账号 |
| R-19 | 返回登录 | 点击“返回登录” | 跳转 `/login` 登录页 |
| R-20 | 响应式-移动端 | 375px 宽度打开注册页 | 卡片单列铺满、无横向滚动；输入框、按钮可正常点击；字号可读 |
| R-21 | 响应式-桌面端 | 1440px 宽度打开 | 卡片居中，宽度不超过 520px，两侧留白均衡 |
| R-22 | 键盘操作 | 仅用 Tab / Shift+Tab 浏览并提交 | 焦点顺序为 用户名 → 手机号 → 密码 → 显示按钮 → 确认密码 → 协议 → 提交；回车可提交 |
| R-23 | 无障碍 | 触发校验失败 | 输入框带 `aria-invalid="true"`，错误文案通过 `aria-describedby` 关联；焦点自动定位到第一个错误字段 |

## 三、服务端校验（自动化）

`mvn test -Dtest=RegistrationValidationTest` 应全部通过，覆盖：

- 用户名：4-20 位字母/数字/下划线，拒绝空、过短、过长、空格、中文
- 手机号：必须 11 位；拒绝 10 位、12 位、以 2 开头、含字母、含空格与连字符；接受 13x/14x/15x/17x/18x/19x 号段
- 密码：8-50 位且同时包含字母和数字
- 确认密码：必须与密码一致

> 服务端与前端规则一致：前端用于即时反馈，服务端（`Validators`）为最终防线，绕过前端直接提交同样会被拒绝。

## 四、兼容性检查清单

- Chrome / Edge / Firefox：实时校验、密码显隐、强度条、提交禁用均正常
- Safari：`input[type=tel]` 唤起数字键盘，`maxlength` 生效
- 移动端：无横向滚动条，点击区域不小于 40px
- 关闭 JavaScript 时：表单仍可提交，由服务端完成校验并回显错误（`novalidate` + 服务端校验）
